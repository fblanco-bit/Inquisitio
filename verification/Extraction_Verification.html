Root cause and chosen approach

The old program split labels, values and wrapped sentences into separate fragments, discarded short fragments, recognized only a few narrowly worded statements, and generally required a matching party name in the same fragment as a value. It also classified the entire combined complaint/crash-report PDF as an allegation and blocked its extracted facts, including a correctly extracted home address. Fifty-two of Form 202’s 81 fields had placeholder targets without a usable extraction path. The correction retains lines and table geometry, links nearby values to an identified party, gives every selected question explicit targets, normalizes comparison values while keeping the original text, and inserts supported responses only after checking their page text, attribution and source hash. Classification changes confidence rather than discarding explicit facts.

I considered expanding the old phrase patterns alone. That would still lose separated labels and values, mixed-person table context and unimplemented question targets. The selected approach uses the requested local libraries inside the existing modules and preserves the current response/approval workflow. It does not add an LLM, cloud processing or a new application architecture.
